Mandhiragiri Jothidam

Postman API Testing Guide

Start the Backend

  1. Start MySQL in the XAMPP Control Panel.
  2. Open PowerShell in the backend project folder. If .env does not exist, create it from the example:
Copy-Item .env.example .env
  1. Install dependencies, apply database migrations, seed the Super Admin, and start the API:
npm.cmd install
npm.cmd run migrate
npm.cmd run seed:admin
npm.cmd run dev
  1. Check http://localhost:5000/api/v1/health. Expect HTTP 200 and database: CONNECTED.

Import and Run the Collection

  1. In Postman, choose Import and select postman/collections/Mandhiragiri API.postman_collection.json.
  2. The collection variable baseUrl defaults to http://localhost:5000/api/v1.
  3. Check adminPhone and adminPassword collection variables against .env. The example defaults are 9876543210 and Admin@1234.
  4. Set unique values for staffPhone and staffEmail before each fresh run. The database rejects duplicates.
  5. Select the collection, click Run, and run requests in the listed order. Scripts save tokens, IDs, and the generated staff password for later requests.

Password note: The final password-change request changes the seeded admin password to PostmanTest@1234. Use that value for a later run. If Postman does not persist the updated collection variable, update adminPassword manually.

Panchangam note: The collection writes clearly marked test values for today's date and Madurai. Replace these with verified astrological data for real use.

Endpoints Covered

  • Health: GET /health, GET /api/v1/health
  • Auth: POST /api/v1/auth/login, POST /api/v1/auth/staff-login, POST /api/v1/auth/refresh, POST /api/v1/auth/logout, GET /api/v1/auth/me, POST /api/v1/auth/change-password
  • Dashboard and Panchangam: GET /api/v1/dashboard/overview, GET /api/v1/panchangam/today, PUT /api/v1/admin/panchangam
  • Bookings and balances: GET /api/v1/schedule/bookings, POST /api/v1/bookings, GET /api/v1/bookings/:bookingId/balance, POST /api/v1/bookings/:bookingId/payments, GET /api/v1/bookings/:bookingId/payments, GET /api/v1/reports/balances
  • Staff: GET /api/v1/staff, POST /api/v1/staff, GET /api/v1/staff/me/dashboard, POST /api/v1/staff/me/leaves
  • Attendance: GET /api/v1/attendance/daily, PUT /api/v1/attendance/record, POST /api/v1/attendance/self
  • Leave: GET /api/v1/leaves/admin/all, POST /api/v1/leaves/admin/:leaveId/decision
  • Events and profile: POST /api/v1/events/:eventId/complete, GET /api/v1/admin/profile, PUT /api/v1/admin/profile

Check Database Rows

Run these queries in phpMyAdmin or a MySQL client:

USE mandhiragiri_db;
SHOW TABLES;

SELECT id, booking_number, total_event_charge, client_total_received,
       priest_total_pay, priest_advance_paid
FROM bookings
ORDER BY id DESC
LIMIT 10;

SELECT booking_id, party, amount, payment_method, reference, paid_at
FROM booking_transactions
ORDER BY id DESC
LIMIT 20;
